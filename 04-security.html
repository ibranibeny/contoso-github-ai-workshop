04 Building Security into the Developer Workflow

14:10–14:3525 minTalk + mini demos

Learn how security can be integrated earlier into the development lifecycle, enabling development and security teams to identify and address potential issues as part of their regular software delivery process.

Key message

Find and fix security issues in the pull request, where developers already work, and let the platform enforce the rules. That applies to code written by people and by AI.

By the end of this session
  • Developers and security teams see where each check runs in the workflow
  • Everyone understands what Copilot Autofix and agentic autofix do, and their limits
  • Leaders know what is included, what is licensed and what is free

Stop secrets before they leak

Secret scanning

  • Scans the whole Git history on all branches, plus issues, pull requests, Discussions, wikis and secret gists. Alerts appear in the repository's Security and quality tab.
  • Partner-format secrets are reported to the issuing provider.
  • The supported-patterns reference lists 531 patterns. Validity checks ask the provider whether a secret is still active.
  • AI-detected secrets (formerly "Copilot secret scanning") finds unstructured secrets such as passwords; it skips test paths.
  • Custom patterns cover Contoso-specific formats, with a dry run before publishing.

Secret scanning · Supported secret scanning patterns · Validity checks

Push protection

  • Blocks secrets in command-line pushes, web commits, file uploads, REST API requests and GitHub MCP server interactions.
  • Repository-level push protection needs Secret Protection and is off by default. Push protection for users is on by default on GitHub.com and blocks pushes of secrets to public repositories.
  • By default, anyone with write access can bypass by giving a reason. Every bypass creates an alert, an audit log entry and an email to owners and security managers.
  • Delegated bypass turns bypass into a request that designated reviewers approve. Requests expire after 7 days.

Push protection · Enabling delegated bypass for push protection

Find and fix code vulnerabilities in the pull request

Code scanning with CodeQL

  • Default setup is the quickest, lowest-maintenance option. It builds the configuration from the repository's code and scans on push and pull requests to the default or protected branches, plus weekly. Enable it under Settings → Security and quality → Advanced Security → CodeQL analysis → Set up → Default.
  • Advanced setup adds a CodeQL workflow for needs default setup doesn't meet, such as custom builds, matrix builds or schedules.
  • Supported languages: C/C++, C#, Go, Java/Kotlin, JavaScript/TypeScript, Python, Ruby, Rust, Swift and GitHub Actions workflows. PHP and Scala are not supported by CodeQL.
  • In a pull request, the Code scanning results check annotates new alerts on changed lines. By default it fails on error, critical or high findings, and the thresholds can be changed.
  • Any tool that produces SARIF can upload results, so Contoso can keep an existing scanner and still see its findings in pull requests.

Secure the supply chain

  • Dependency graph: built from manifests, lock files and the submission API; exports an SBOM.
  • Dependabot alerts fire when a new advisory affects a dependency. Alerts can be assigned to Copilot or a third-party agent, which opens a draft pull request with a fix. Note: actions pinned to a commit SHA get no Dependabot alerts.
  • Dependabot security updates raise a pull request to the minimum patched version; version updates keep dependencies current from .github/dependabot.yml, with grouping to cut pull request noise.
  • Dependency review shows added, removed and updated dependencies in the pull request diff, with vulnerabilities. Its action fails by default on vulnerable packages; make it required through a ruleset.

Dependabot alerts · Dependency review · Enforcing dependency review across an organization

Secure the pipeline itself

Harden GitHub Actions

  • Default GITHUB_TOKEN to read-only and raise permissions per job.
  • Pin third-party actions to a full-length commit SHA; workflow dependency lockfiles Public preview are the stronger option where adopted.
  • Use OpenID Connect instead of long-lived cloud secrets: short-lived tokens valid for one job.
  • Avoid pull_request_target with untrusted code; CodeQL can scan workflow files.

Prove where artifacts came from

Artifact attestations create signed build provenance with actions/attest@v4, verified with gh attestation verify. On Free, Pro and Team plans they work on public repositories only; private and internal repositories need Enterprise Cloud.

AI-written code goes through the same gates

Code from Copilot is still code. GitHub documents these protections for the Copilot cloud agent:

  • It checks its own changes with CodeQL, checks new dependencies against the GitHub Advisory Database (malware and High/Critical CVSS vulnerabilities) and runs secret scanning, all without a GitHub Advanced Security licence. It then tries to fix what it finds, and details appear in the session log.
  • It opens draft pull requests that a human must review and merge; it cannot approve or merge, and the person who asked for the work cannot approve it either.
  • It is subject to branch protections, rulesets and required checks, and Actions workflows on its pull requests wait for approval.

Copilot code review checks for bugs, security issues and style, but GitHub states it is not guaranteed to catch everything and it skips dependency files such as package.json. Pair it with code scanning and human review.

Govern at scale

Rulesets

Require pull requests with approvals and code-owner review, required status checks, and Require code scanning results. Up to 75 rulesets per repository and per organization; overlapping rules combine and the strictest wins.

Knowledge check

3 quick questions

Answers come from this page. Nothing is sent anywhere.

  1. When does push protection stop a secret?

    Push protection blocks secrets in command-line pushes, web commits, file uploads, REST API requests and GitHub MCP server interactions. A bypass needs a reason and is audited.

  2. Who counts towards GitHub Secret Protection and GitHub Code Security licences?

    Both products are licensed per unique active committer.

  3. What does Copilot Autofix do?

    Autofix proposes a fix inside the pull request and a developer decides. With agentic autofix you can also assign alerts to Copilot, which fixes, rechecks with CodeQL and opens a draft pull request.

Demo: push protection with a made-up Contoso token

GitHub Docs offer no official test token for demos. The documented, safe route is a custom pattern for a made-up format, with push protection enabled for it. Set it up beforehand (organization or repository Settings → Advanced Security → Custom patterns):

  • Name: Contoso demo token · Secret format: contoso_demo_[a-z0-9]{32}
  • Test string: contoso_demo_0123456789abcdef0123456789abcdef → Save and dry run → publish → Enable push protection for the pattern. The Enable button appears only after a successful dry run and publish.
  • Repository push protection must be on; custom patterns need Secret Protection on an organization-owned repository.

Likely questions

  • "Do we need Copilot licences for Autofix?" No. Copilot Autofix comes with Code Security on private repositories and is free on public ones.
  • "We already have a SAST tool." Keep it: upload its SARIF output and the findings appear in pull requests next to CodeQL.
  • "Does secret scanning look at old commits?" Yes, the whole Git history on all branches.
  • "How is it priced?" Per unique active committer (90 days), per product. The free risk assessment helps size the problem first.
