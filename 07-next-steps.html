Agenda / Session 7

07 Discussion, Use Cases & Next Steps

16:10–16:3020 minFacilitated discussion

Interactive discussion to identify relevant opportunities and use cases across Contoso, with a focus on developer productivity, application modernization, secure development, and AI-assisted software engineering.

Key message

Start where the value is clear and the risk is low, measure it honestly, and grow from evidence. Leave today with three prioritized use cases and named owners.

Outputs of this session
  • A list of Contoso use cases across four lenses
  • The top three, placed on a value-versus-feasibility grid
  • An agreed next step with an owner and a date

Four lenses for Contoso use cases

Each lens lists starter ideas tied to capabilities shown today. Use them to prompt the room, not as the answer.

Lens 1

Developer productivity

  • Raise test coverage on under-tested services (Chat /tests, cloud agent tasks)
  • Shorten pull request turnaround with Copilot code review as a first pass
  • Onboard people to legacy codebases faster ("explore a codebase" prompts, Spaces)
  • Diagnose CI failures from the terminal with Copilot CLI
  • Standardize conventions with instruction files and prompt files
Lens 2

Application modernization

  • Upgrade Java (Maven or Gradle; Java 8, 11, 17, 21, 25) and .NET applications with GitHub Copilot modernization
  • Migrate applications to Azure (App Service, Container Apps, AKS) with predefined tasks, for example moving to managed identity
  • Assess and plan many applications at once with the Modernize CLI
  • Burn down technical debt with well-scoped cloud agent tasks

Analyze Applications and Migrate to Azure by Using GitHub Copilot Modernization (Microsoft Learn)

Lens 3

Secure development

  • Find exposed secrets with the free secret risk assessment, then turn on push protection
  • Enable CodeQL default setup and Copilot Autofix on the most critical applications
  • Dependency hygiene with Dependabot and a required dependency review check
  • Burn down an existing alert backlog with security campaigns and agentic autofix
Lens 4

AI-assisted software engineering

  • Hand backlog items (bugs, accessibility, docs) to the cloud agent
  • Custom agents that encode team standards, for example a test-coverage or migration agent
  • Spec-driven development for new services (Spec Kit)
  • Repository chores with GitHub Agentic Workflows Public preview, for example issue triage and reports

Next-step options

A · GitHub Copilot pilot

Follow GitHub's guidance for a pilot: define success criteria (adoption, cost, feedback), estimate AI-credit cost and set a budget ceiling, enable the pilot group, monitor, then make a go/no-go decision.

  • Success signals from the docs: 70–90% of trial licences used in the first month; daily and weekly active users stable or rising; use across languages and features; agent adoption; positive developer feedback.
  • Enablement timeline example: start onboarding 45 days out with success metrics and champions; announcements at 14 days; a workshop at 7 days; a support channel on launch day.

Pilot a new Copilot feature or model in your enterprise · Measuring the success of a GitHub Copilot trial · Driving GitHub Copilot adoption in your company

B · Security assessment and rollout

Start with the free secret risk assessment and the code scan of up to 20 active repositories (available to GitHub Team and Enterprise organizations). Then follow GitHub's six-phase rollout:

  1. Align on strategy and goals
  2. Prepare to enable at scale
  3. Run pilot programs
  4. Create internal documentation
  5. Roll out code scanning
  6. Roll out secret scanning

Introduction to adopting GitHub Advanced Security at scale

C · Modernization pilot

Pick one or two Java or .NET applications with a clear upgrade or Azure migration target. Run assessment and planning, then upgrade in the IDE with GitHub Copilot modernization. Generally available today: IDE upgrades (.NET, Java, C++), IDE migrations (.NET, Java), and the CLI for assessment and planning.

GitHub Copilot Modernization for Java Developers · GitHub Copilot modernization overview (.NET)

D · Platform foundations and skills

  • Decide the enterprise type: Enterprise Cloud with Enterprise Managed Users on Entra ID, and whether data residency is needed.
  • Set enterprise policies, audit log streaming and Copilot budgets before scaling.
  • Skills: Microsoft Learn paths and GitHub certifications (GH-900, GH-300, GH-500, GH-200, GH-100). See Resources.

Facilitation guide

Questions that get a room talking

  • "Which application would you choose for a pilot tomorrow, and why that one?"
  • "What would have to be true for security to say yes?"
  • "If a developer saved an hour a day, where should that hour go?"
  • "Which backlog has been growing for a year? Tests, upgrades, vulnerabilities?"

Techniques

  • Silent writing for 3 minutes before discussion, so quieter voices are heard.
  • Three dots per person for voting, with a maximum of two on any one idea.
  • Close the parking lot explicitly: answered, assigned to follow-up, or out of scope.

Close the afternoon (last 2 minutes)

  • Thank the sponsors, read back the three use cases and owners, and confirm the date of the follow-up meeting.
  • Share this site's link and the feedback survey.
