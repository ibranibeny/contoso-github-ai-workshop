Agenda / Session 2

02 GitHub as an AI-Powered Developer Platform

13:15–13:4025 minTalk + walkthrough

Discover how GitHub brings together collaboration, AI-assisted development, security, and DevOps capabilities to support the complete software development lifecycle and help organizations deliver software more efficiently.

Key message

GitHub is one platform where planning, code, AI, security and delivery share the same repositories, identities and policies. Context flows between them for people and for AI.

By the end of this session
  • The room can name the five capability areas and what each one does
  • Security, platform and IT leaders know the enterprise controls: identity, data residency, audit and policy
  • Everyone understands how Copilot and GitHub Advanced Security are packaged today

The platform on one page

Plan and collaborate

Repositories and pull requests

A repository holds code, files and their full revision history. It can be public or private. Organizations owned by an enterprise on GitHub Enterprise Cloud can also use internal visibility for inner source. A pull request proposes a change. Its tabs include Checks and a Findings tab that collects automated review results such as code scanning alerts.

About repositories · Pull requests

Issues, sub-issues and issue types

Issues track bugs, features and tasks, with "blocked by / blocking" dependencies. A parent issue can have up to 100 sub-issues, nested up to eight levels deep. Organizations define up to 25 issue types; the defaults are task, bug and feature.

About issues · Adding sub-issues · Managing issue types in an organization

GitHub Projects

Table, board and roadmap views over issues and pull requests, kept in sync in both directions. Up to 50 fields per project, plus built-in automations, charts, templates and status updates. This is where a business stakeholder can follow progress without reading code.

About Projects

Discussions

A forum for announcements, Q&A with marked answers, and polls, at repository or organization level. Useful for an internal Copilot or platform community. An admin enables it, and issues can be converted into discussions.

About discussions

Build with AI

Copilot is not one feature but a set of surfaces: the IDE (VS Code, Visual Studio, JetBrains, Eclipse, Xcode), GitHub.com, GitHub Mobile, the terminal (Copilot CLI) and the desktop GitHub Copilot app. On GitHub.com, Copilot offers chat, agentic multi-step tasks, pull request code review, and automations that run on a schedule or on repository events. Session 3 covers the developer experience in depth, and Session 6 covers agents.

GitHub Copilot on GitHub.com

Copilot plans for companies

Since 1 June 2026, Copilot usage is billed in GitHub AI Credits (1 credit = USD 0.01). The older "premium requests" model is now legacy. Seat prices did not change.

Secure

GitHub Advanced Security is now sold as two products. Either one requires a GitHub Team or GitHub Enterprise plan. Licences are counted per unique active committer, meaning anyone who pushed a commit in the last 90 days.

GitHub Secret Protection
  • Secret scanning and push protection
  • AI-detected secrets and custom patterns
  • Delegated bypass and delegated alert dismissal
  • Security campaigns and security overview
GitHub Code Security
  • Code scanning (CodeQL or third-party tools) and the CodeQL CLI
  • Copilot Autofix and AI Scan
  • Security campaigns and custom Dependabot auto-triage rules
  • Dependency review and security overview

Included on every plan: the dependency graph and Dependabot alerts. Public repositories get code scanning, secret scanning and dependency review at no cost. AI Scan and agentic autofix also consume Code Security AI Credits, drawing first on any credits included with Copilot. Session 4 goes deeper.

About GitHub Advanced Security · GitHub Advanced Security license billing

Automate and deliver

GitHub Actions

GitHub's CI/CD and automation platform. Workflows are YAML files in .github/workflows that run on repository events, on a schedule or manually; each job runs on a runner. GitHub-hosted runners (Ubuntu, Windows, macOS) give every job a fresh VM hosted in Azure, with images maintained by GitHub.

Understanding GitHub Actions · GitHub-hosted runners

Larger runners

Available on GitHub Team and Enterprise Cloud. They add more CPU, RAM and disk, GPUs, static IP addresses, Azure private networking, runner groups, autoscaling and custom images. Larger runners are always billed per minute; included minutes never apply to them.

Larger runners

GitHub Packages

Hosts packages next to the code, with the same permissions and billing. Supports npm, RubyGems, Maven, Gradle, Docker and NuGet, and its Container registry handles Docker and OCI images.

Introduction to GitHub Packages

GitHub Codespaces

Cloud development environments: a Linux container on a VM from 2 cores / 8 GB RAM / 32 GB storage up to 32 cores / 128 GB / 128 GB. You open a codespace in the browser, VS Code or GitHub CLI and define it as code with dev containers, so every contributor gets the same ready-made environment.

What are GitHub Codespaces?

Included Actions minutes per month on standard runners: 2,000 for Free organizations, 3,000 on Team and 50,000 on Enterprise Cloud. Standard GitHub-hosted runners are free for public repositories, and self-hosted runners are free. (GitHub's plans)

Enterprise Managed Users

Your identity provider creates and manages GitHub accounts. Partner providers are Microsoft Entra ID, Okta and PingFederate. With OIDC, GitHub can apply Entra ID Conditional Access policies. Managed users cannot create public content or collaborate outside the enterprise.

About Enterprise Managed Users

Data residency (GHE.com)

Regions offered: EU (including Azure regions in Norway and Switzerland), Australia, US and Japan. Each enterprise gets a dedicated GHE.com subdomain, must use managed users and cannot have public repositories. An optional policy keeps Copilot processing in-region, in the US and EU only, and adds 10% to AI credit consumption.

About GitHub Enterprise Cloud with data residency · GitHub Copilot with data residency

Audit, SSO and policy

The enterprise audit log covers 180 days (Git events: 7 days) and can be searched, exported, streamed or queried by API. SAML SSO set at enterprise level applies to every organization. Enterprise policies control settings across all organizations, and none are enforced by default.

Audit log for an enterprise · Enterprise policies

Not yet on GHE.com

macOS runners, Maven and Gradle in GitHub Packages, GitHub Marketplace and some preview features are not yet available with data residency. If Contoso needs data residency, check the feature overview early.

Ask the room

  • "Which identity provider do you use, and must development data stay in a specific region?"
  • "Where do security findings get tracked today: in the developer's tools or somewhere else?"

Likely questions

  • "Can we use Copilot with GitHub Enterprise Server?" Quote the plans page: not currently available for Enterprise Server. Copilot licences come through a cloud enterprise account.
  • "Can our data stay in Asia?" The documented GHE.com regions are EU, Australia, US and Japan. In-region Copilot processing is US and EU only. Check the page again before committing, because regions can be added.
  • "Can we cap Copilot spend?" Yes: turn off the AI credits paid usage policy and set budgets per cost center, organization or enterprise. The docs note there is no automatic fallback to cheaper models when a budget runs out.
