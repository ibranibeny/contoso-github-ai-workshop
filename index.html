Why this workshop

The shift

AI now does work, not just suggestions

GitHub Copilot has grown from code completion into chat, agent mode in the editor and a cloud agent (formerly the coding agent) that takes an issue and opens a pull request. Teams have to decide where that helps and how people stay in control.

The platform

One place for the whole lifecycle

When issues, code, reviews, security findings and deployments live in one platform, context flows between them, for developers and for the AI that works alongside them.

The guardrails

Security and governance by default

Security checks run inside the pull request, where developers already work, and enterprise policies, audit logs and review rules stay in force as AI use grows.

Who should attend

  • Engineering managers, tech leads and architects
  • Developers who will use, or already use, GitHub Copilot
  • Application security and risk teams
  • Platform, DevOps and IT operations teams
  • IT and digital leaders who set tooling and AI policy

What you will leave with

  • A current picture of GitHub Copilot, GitHub Advanced Security and GitHub Actions, with the release status and plan of each feature as GitHub Docs states it
  • One end-to-end reference flow, from requirement to production, that your teams can repeat
  • A shortlist of prioritized Contoso use cases and an agreed next step: a pilot, an assessment or an enablement plan

How the afternoon fits together

The first four sessions build the story one layer at a time. After the break, the live demo puts every layer to work on one real-looking requirement. The last two sessions look ahead and turn what Contoso has seen into next steps.

How to use this site

Participants

Each session page explains the key ideas, links the GitHub Docs pages they come from, and ends with things to try after the workshop.

Facilitators

The yellow Facilitator panels hold the run of show, talking points, questions for the room and likely Q&A. Use the button in the top bar to show or hide them; this browser remembers your choice.

Demo driver

The live demo runbook has every prompt, configuration file and fallback. Preparation steps are in the facilitator guide.

Before the workshop

Participants

  • Bring one or two real friction points from your team's delivery process, such as slow reviews, test debt, legacy code or security backlog. They feed the closing discussion.
  • Optional: read About GitHub Copilot on GitHub Docs.
  • Nothing needs installing; every demo runs on the presenter's machine.

Organizers

  • Confirm date, venue and the attendee mix (developers, security, platform and IT leaders).
  • Give the presenter a wired or stable network that can reach github.com and the Azure portal.
  • Walk through the preparation checklists with the demo driver two weeks out.
How to open the day (2 minutes before Session 1)
  • Welcome, introductions of the Microsoft team and Contoso sponsors, and housekeeping (break at 14:35, exits, Wi-Fi).
  • Set the contract: questions welcome at any time; deep dives go to a visible parking lot that is answered in Session 7 or in follow-up.
  • Ask the room for a quick show of hands: who uses an AI coding assistant today, and who has tried an agent that opens pull requests? Note the answers; Session 6 refers back to them.
  • Appoint a note-taker for use cases. Every "we could use that for…" comment goes on the Session 7 canvas.
