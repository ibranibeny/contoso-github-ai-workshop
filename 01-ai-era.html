Agenda / Session 1

01 Opening & Software Development in the AI Era

13:00–13:1515 minKeynote

Explore how AI is transforming modern software development and the way organizations plan, build, secure, and deliver applications. We will discuss key trends shaping the future of developer experience and software engineering.

Key message

AI is moving from suggesting code to doing delegated work across the whole lifecycle. The organizations that benefit pair it with one platform, clear guardrails and honest measurement.

By the end of this session
  • Everyone shares one picture of how AI now shows up in plan, build, review, secure and deliver
  • The room knows the difference between assistive and agentic AI
  • We agree how Contoso should judge success: outcomes, not activity

The numbers behind the shift

GitHub's annual Octoverse report is the broadest public view of how developers work. The latest edition, Octoverse 2025, was published on 28 October 2025 and updated on 28 February 2026. Headline findings:

Developers

180M+

More than 36 million developers joined GitHub in a year, more than one every second.

AI from day one

~80%

Nearly 80% of new developers use GitHub Copilot in their first week.

Delivery volume

43.2M

Pull requests merged per month on average, up 23% year on year; nearly 1 billion commits pushed (+25.1%).

AI in products

1.1M+

Public repositories using an LLM SDK, up 178% year on year.

Two more signals matter for this afternoon. In August 2025, TypeScript became the most-used language on GitHub, ahead of Python and JavaScript. And the average time to fix critical vulnerabilities fell from 37 to 26 days.

Source: Octoverse 2025 (GitHub blog). These are GitHub's own platform statistics. No 2026 edition had been published when this site was compiled; GitHub Universe runs on 28–29 October 2026, so check for a newer report before you present.

From autocomplete to agents

GitHub Docs now group Copilot capabilities into four families: assistive (suggestions, answers, explanations), agentic (multi-step work toward a goal), customizations (instructions, reusable prompts, skills, custom agents) and external agents, models and tools. Naming note

The feature many people know as the Copilot coding agent is now called Copilot cloud agent in GitHub Docs. The GitHub changelog of 1 April 2026 announced the new name, along with the ability to work on a branch without opening a pull request, to write implementation plans and to do deep research. This site uses the current name throughout.

What changes across the lifecycle

GitHub's own description of the end-to-end flow is short: work starts as an issue, an agent picks it up, it comes back as a pull request, is reviewed for quality and security, and is merged. Here is how that maps to each stage, using capabilities documented today:

PlanRequirements become well-formed issues faster; agents can research and propose implementation plans.Copilot creates issues and sub-issues from a prompt Public preview; the cloud agent researches and plans; GitHub Projects

ReviewEvery pull request can get a first-pass review within seconds, before a human looks at it.Copilot code review; pull request summaries
TestTests are cheaper to write, and agents run tests and linters to check their own work./tests in Chat; the cloud agent runs tests and linters in its cloud environment

What this means for Contoso

1 · The developer's job shifts

More time goes into describing the work well, reviewing what AI produced and deciding what ships. Clear issues and acceptance criteria become engineering assets.

2 · Context is the new configuration

Instruction files, tests and well-structured repositories decide how useful AI is. Teams that write down their standards get better output from every Copilot surface.

3 · Guardrails belong in the platform

Branch rules, required reviews, security checks, policies and audit logs apply to humans and agents alike, without relying on individual discipline.

4 · Measure outcomes, not activity

GitHub's guidance treats pull request throughput and engineering goals as better signals than counting active users. Plan the baseline before the pilot starts.

How GitHub suggests measuring impact

  • Start from engineering goals. GitHub's Engineering System Success Playbook recommends three steps: identify the barriers, work out what is needed, then implement, monitor and adjust. GitHub Docs include goal-specific guides such as increasing test coverage, accelerating pull requests and reducing security debt. (Achieving your company's engineering goals with GitHub Copilot)
  • Follow four phases: choose metrics, monitor adoption, see how code is generated, and connect adoption to engineering outcomes. (Measure and demonstrate the impact of GitHub Copilot)
  • Use the built-in data: a usage metrics API, a 28-day usage dashboard, a code generation dashboard, an impact dashboard and NDJSON export. Users are grouped into adoption cohorts: Code first, Agent first and Multi-agent. (GitHub Copilot usage metrics)
  • Read ROI figures with care. The impact dashboard links cohorts to pull request throughput. Its "potential return on investment" numbers are directional estimates, not financial results. (Viewing the Copilot impact dashboard)
  • Trial benchmark: GitHub suggests that 70–90% of trial licences should show usage within the first month. (Measuring the success of a GitHub Copilot trial)
Vendor-cited figures

GitHub's enterprise overview cites a Total Economic Impact study: developers save 45 minutes a day and onboarding and training time falls by 40%. Present these as figures GitHub cites from a commissioned study, not as a forecast for Contoso. A Contoso pilot with its own baseline is the evidence that counts. (About GitHub for enterprises)

Ask the room

  • "Between an idea and production, where does a change spend most of its time in your teams?"
  • "What would you never let an AI agent do on its own?" Write the answers on the parking lot; Session 6 maps each one to a guardrail.

Likely questions

  • "Is Copilot trained on our code?" GitHub Docs state that GitHub does not use Copilot Business or Enterprise customer data to train models, and that this data is covered by GitHub's Data Protection Agreement. Since 24 April 2026, interactions on Free, Pro, Pro+ and Max may be used for training unless the user opts out. That is one reason to use company-managed licences. (Managing GitHub Copilot policies as an individual subscriber)
  • "Are the productivity claims real?" Point to the measurement guidance above. The honest answer is to measure Contoso's own baseline and pilot rather than rely on anyone's averages.
  • "Will AI replace developers?" Keep the answer to what the docs describe: humans assign, review, approve and merge, and agents cannot approve or merge their own pull requests (see Session 6).
