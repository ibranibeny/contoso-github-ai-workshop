Agenda / Session 6

06 The Next Evolution: Agentic Software Development

15:45–16:1025 minTalk + demo

Explore the emerging evolution from AI-assisted development toward agentic software development, and how AI is changing the way development teams approach the software engineering lifecycle.

Key message

Agentic development means delegating whole tasks to agents that work in parallel, and the engineering job moves toward specifying, reviewing and governing that work. GitHub builds the guardrails into the platform so that delegation stays safe.

By the end of this session
  • The room can tell assistive AI from agentic AI, and knows which tasks suit agents
  • Everyone knows where agents run today and what is GA versus preview
  • Leaders know the governance controls: policies, approvals, audit and cost

From assistant to agent

GitHub Docs separate assistive capabilities (suggestions, answers, explanations) from agentic ones: work toward a goal over multiple steps, using tools, with a human reviewing the result. In the live demo you saw both. Agent mode worked with the presenter in the editor; the cloud agent worked for the team in the background and came back with a pull request.

Copilot cloud agent

Formerly the Copilot coding agent. The cloud agent researches a repository, plans, and makes changes in the background in a temporary cloud environment where it can run tests and linters. You can start it from the Agents tab or panel, a chat, an issue or a pull request. It has been generally available for all paid Copilot plans since 25 September 2025 (GitHub changelog).

Good first tasks

  • Bugs with a clear reproduction
  • UI changes and accessibility improvements
  • Increasing test coverage
  • Documentation
  • Technical debt with a clear definition of done

Keep for humans (per GitHub's guidance)

  • Broad cross-repository refactors and changes that need one consistent design
  • Deep domain or business logic, and legacy dependencies
  • Production-critical, security, personal-data and authentication work, and incident response
  • Ambiguous tasks, and tasks a developer should do to learn
  • Write issues like a brief to a new teammate: a clear problem statement, acceptance criteria and hints about which files to change. The agent also reads .github/copilot-instructions.md, *.instructions.md, AGENTS.md, CLAUDE.md and GEMINI.md.
  • Prepare its environment with .github/workflows/copilot-setup-steps.yml so dependencies are installed before it starts.
  • Limits: one repository, one branch and one pull request per task; a session runs for at most 59 minutes; GitHub-hosted repositories only.
  • Iterate on the pull request: mention @copilot in a comment, or use Fix with Copilot on review comments, failing workflow runs and merge conflicts.

Customize agents for Contoso's way of working

Custom agents

A Markdown profile with YAML frontmatter (description is required; name, tools, mcp-servers and target are optional) and a prompt of up to 30,000 characters. Locations:

  • Repository: .github/agents/NAME.agent.md
  • Organization: agents/ in the org's .github or .github-private repository
  • Enterprise: the .github-private repository of a designated organization

Usable from the cloud agent (dropdown, issue assignment, pull requests), Copilot CLI (/agent), the Copilot app and IDEs.

Model Context Protocol (MCP)

  • The cloud agent comes with the GitHub MCP server (read-only, current repository) and Playwright (localhost only).
  • Repository MCP settings are shared by the cloud agent and code review. The cloud agent calls MCP tools without asking, so allowlist read-only tools.
  • The GitHub MCP Registry Public preview lists curated servers. Enterprises allowlist servers with a managed settings file.
  • For Business and Enterprise seats, the MCP servers in Copilot policy is off by default.

Agentic beyond writing code

Review

Copilot code review gathers context from the whole project using Actions runners and can use the repository's MCP servers and skills. Handing its suggested fixes to the cloud agent is in public preview.

Security remediation

Agentic autofix takes up to 25 code scanning alerts and opens a draft pull request. Dependabot alerts can be assigned to Copilot or a third-party agent. See Session 4.

Repository automation

GitHub Agentic Workflows Public preview: Markdown instructions compile to a hardened .lock.yml Actions workflow. Read-only by default, with writes only through declared "safe outputs", secrets kept from the agent, and a default cap of 1,000 AI credits per run.

GitHub Agentic Workflows

Spec-driven development

Spec Kit is GitHub's MIT-licensed open-source toolkit that gives coding agents a structured process: /speckit-constitution → /speckit-specify → /speckit-plan → /speckit-tasks → /speckit-implement. Treat it as an open-source project: check its support model before you depend on it.

github/spec-kit repository

Retired or retiring, so leave them out of plans

The gh copilot CLI extension stopped working on 25 October 2025 (replaced by Copilot CLI). GitHub Models retired on 30 July 2026. GitHub Spark has taken no new users or apps since 4 August 2026. (GitHub changelog)

Guardrails: how delegation stays safe

Concern from the roomDocumented control
"Who can make the agent do things?"Only users with write access can trigger it; comments from others never reach it. For Business and Enterprise, the cloud agent is disabled by default until an admin enables it, and repository access can be limited.
"Can it push to production?"It pushes only to its own copilot/ branch, cannot run raw git push, and is subject to rulesets and required checks.
"Can it approve its own work?"No. It opens draft pull requests that a human must review and merge. The requester cannot approve, and Actions workflows wait for approval by default.
"What can it reach on the internet?"A firewall is on by default with a recommended allowlist; hidden characters, such as HTML comments in issues, are filtered from its input.
"How do we audit it?"Commits are signed and link to session logs. The audit log records agent activity: filter with actor:Copilot, use fields such as actor_is_agent and agent_session_id, keep 180 days, and stream to a SIEM.
"How do we control cost?"Agents consume AI credits and Actions minutes. Use budgets per user, cost center, organization or enterprise, and decide whether paid usage beyond included credits is allowed.

What changes for Contoso's teams

Developers

Spend more time writing good issues and specs, reviewing agent pull requests and handling the hard problems. Tests become the safety net that lets agents move fast.

Platform team

Owns setup steps, instruction files, custom agents, firewall allowlists and MCP allowlists, the "paved road" agents run on.

Security & leadership

Owns rulesets, validation tools, policies, budgets and audit streaming, and decides which repositories agents may work in.

Demo: plan first, then delegate sub-issue (3)

  1. Open the repository's Agents tab and start a task, selecting the custom agent if you created one:
    Prompt · Agents tab

    Research how order lookups flow through src/ and write an implementation plan for sub-issue #<audit sub-issue>: record every order lookup (order ID, agent user ID, timestamp, result) without logging customer contact details. Don't open a pull request yet.

    A task started from the Agents tab works on a branch first, so you can review the plan and diff before a pull request exists.
  2. While it runs, open the session log and show the steering box: "add a note about retention".
  3. Show the plan, then ask it to implement and open a pull request, or stop there for time.

Likely questions

  • "Can we use Claude or Codex?" Yes, as third-party coding agents in public preview on all paid plans, once enabled in policy. They run with the same protections and their GitHub App actions appear in the audit log.
  • "Does the agent see our internal systems?" Only through MCP servers you configure, plus the firewall allowlist. Remote MCP servers that use OAuth are not supported for the cloud agent.
  • "Can we restrict it to some repositories?" Yes: repository access in the organization's cloud agent settings, and enterprise policies on top.
